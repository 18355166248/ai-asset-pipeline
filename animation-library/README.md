# 枢轴动作库

2D 游戏用的分层枢轴动画数据。**纯数据，不含代码** —— 消费它的工具在 `../src/blender/`。

这样组织是为了将来能独立出去：真需要变成单独仓库时，
`git subtree split --prefix=animation-library` 就能整段拆走，不用理顺代码依赖。
目前不拆，因为唯一的消费者就在同一个仓库里，分家只会带来同步负担。

## 这是什么

不是骨骼蒙皮动画，是**分层枢轴动画**：每个部件的原点建在自己的关节上，
靠给 `rotation_euler` 打关键帧驱动，父件带子件。没有骨骼、没有蒙皮权重。

对 2D 游戏够用的原因：单位在屏幕上只有 64–96px，
刚性肢体旋转和蒙皮形变在这个尺寸下肉眼无差别。
而且它对人形 / 四足 / 怪兽一视同仁——枢轴是自己定义的，
不依赖任何"这是个人形"的先验，也就不需要动作捕捉数据。

## 已验证：四足零代码接入

加 `quadruped-basic` 时**没有改动任何一行工具代码**——
新增骨架和动作都只是数据，`make_test_rig.py --skeleton quadruped-basic` 直接就跑通了，
两道闸门也照常工作。这验证了枢轴动画对非人形同样成立：
枢轴是自己在骨架里定义的，不依赖任何"这是个人形"的先验，
也就不需要四足动作捕捉数据（那类数据恰恰是最难搞的）。

四足特有的几点：

- **对角步态**：左前+右后同相，右前+左后反相。这是最易读的四足步态。
- **前后腿关节方向相反**：前腿膝向后折，后腿跗关节向前折。弯反了一眼就是"错的动物"。
- **脊柱要参与**：扑咬的爆发力全在脊柱先弓后展，只动腿会像玩具。
- **尾巴逐节延迟**：三节尾巴各晚 3 帧，就有鞭子感。这是层级枢轴最直观的红利。
- **用宽画面**：长身体的四足渲进正方形画面会浪费大量像素，
  `--frame-height 168` 配 256 宽，有效分辨率显著提高。

**复用机制**：动作绑定的是 `skeleton` id，不是具体角色。
任何按 `humanoid-basic` 搭出来的角色都能直接套这八个动作。
换角色只要换几何，动作数据原样复用。

## 骨架格式

```json
{
  "id": "humanoid-basic",
  "axes": { "lateral": "X", "forward": "Y", "up": "Z", "swingAxis": "X" },
  "materials": { "cloth": [0.16, 0.30, 0.34, 1] },
  "parts": [
    { "id": "arm-r-upper", "parent": "torso", "joint": [-0.30, 0, 1.44],
      "shape": { "type": "box", "size": [0.16, 0.17, 0.46],
                 "offset": [0, 0, -0.20], "material": "cloth" } }
  ]
}
```

`joint` 是该部件的**旋转中心**，几何靠 `offset` 从关节往外长。
`shape` 为 `null` 表示是纯变换节点（如 `root`）。

**轴向约定**：X 分左右、Y 是朝向，所以前后摆动绕 X 转。
写成绕 Y 会让左右分离和前后摆动共用一个轴——正面看像开合跳，侧面看人薄成一条线。

## 动作格式

```json
{
  "id": "slash",
  "skeleton": "humanoid-basic",
  "end": 24,
  "loop": false,
  "notes": "前摇 8 帧（慢）→ 挥出 3 帧（快）→ 定格 4 帧 → 收招 9 帧。",
  "render": { "frames": 12 },
  "tracks": {
    "arm-r-upper": { "rot": [[1, [20, 0, 0]], [9, [86, 0, 0]], [12, [-92, 0, 0]]] },
    "torso": { "scale": [[1, [1, 1, 1]], [12, [1.06, 1, 0.94]]] }
  }
}
```

三个通道：`rot`（欧拉角，度）、`loc`（**相对建模位置的偏移**，不是绝对坐标）、
`scale`（倍数）。关键帧写成 `[帧号, [x, y, z]]`，紧凑且好 diff。

## 调参要点

手感靠这三样，缺一件就"像在滑"：

1. **重心起伏** —— 走路时 `root` 上下颠，触地最低、过渡帧最高。只转腿不颠髋 = 滑步。
2. **跟随延迟** —— 小臂比大臂晚 2~3 帧到达极值。同步到位的肢体没有重量。
3. **蓄力与收招** —— 帧数分配就是打击感。挥出只占 3 帧所以显得快，定格 4 帧让力道落地。

`scale` 通道的挤压拉伸是小尺寸下最有效的力道提示：命中帧压扁、起跳拉长、落地压扁。

放技能和挥砍的区别在于**有一段可读的蓄力保持**——挥砍是瞬发，
技能要让玩家看见在攒东西，所以中段几乎不动。

## 两道闸门，改完动作先跑

```bash
# 1 校验数据本身：部件是否存在、循环首尾是否接得上、帧号是否越界
python ../src/validate_clips.py

# 2 校验导出结果：GLB 里的烘焙值是否和库里声明的一致
python ../src/verify_rig_export.py --rig-dir ../output/rig
```

第二道尤其重要：**动画在导出环节丢失时全程不报错**。
实测踩过一次——glTF 导出器默认把 11 个部件拆成 11 条独立动画，
重新导入只有一条激活，成品是"角色几乎不动"，而导出返回 FINISHED、导入无警告。
这道闸能直接指出该开哪两个开关。

## 加新动作

1. 在 `clips/humanoid-basic/` 建 JSON，`skeleton` 填 `humanoid-basic`
2. 在 `library.json` 的 `clips` 里登记
3. 跑 `validate_clips.py`
4. 生成并渲染，再跑 `verify_rig_export.py`

循环动作有个硬要求：每条轨道都必须覆盖首帧 1 和末帧 `end`，且两端姿态一致。
校验脚本会查这条——它渲染时不报错，但播放时每圈都会在接缝处顿一下。
