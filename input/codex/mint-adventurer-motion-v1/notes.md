# 二次元角色样片检查（2026-10-02）

角色设计为可爱二次元冒险家，二维彩色原画，未生成 GLB 或三维模型。reference.png 是身份参考，不是已绑定骨骼的模型。

## 真实结果

- reference.png：已生成，原生 RGBA，保持源图。头部侧面、躯干带有少量三分之四视角，因此尚不是严格正交的角色设定。
- walk-v1.png：1536×1024，四列两行。左右腿的第二半周期不可靠，过脚姿势不完整，拒绝作为完整步行循环。
- walk-v2.png：同尺寸，一次定向修正。第 3、7 格出现双脚靠近的姿态，但第二半周期仍重复同侧腿；面部/袖子/腰包细节也有漂移。仍为 rejected-candidate。
- 逐格 alpha 等分导出，保留原顺序。全片统一缩到 192×256 单元格，不逐帧按 bbox 自动裁切、拉伸或挪动脚底来遮掩生成问题。
- 试播 100ms/帧、8 帧，周期 800ms。这个参数用于检查候选，不是 X 视频的真实帧率。
- 尚未生成待机、攻击、受击、跳跃。先解决步态，不扩散失败方法生成全套图集。
- 尚未接入连续视频生成；无视频抽帧产物，无游戏运行时替换。

## 对新帖子的核对

原帖：[Sprite-gen + Grok](https://x.com/aldegadwildkim/status/2105936385937195463?s=46)。2026-10-02 浏览器初始曾提示无法播放，点击播放后实际成功；已观察不同播放时间的画面。DOM 显示展示视频 720×1078、约 9 秒，并非测出了单个步态周期长度。它同时展示红发角色的八个朝向，镜头和角色位置稳定；侧面有交替迈步、身体起伏与头发摆动，个别画面抬膝较高。未取得逐帧导出，未测出播放帧率、脚底滑移或循环接缝误差，不做数值评分。

帖子正文只写 Sprite-gen + Grok，不能把全部仓库参数认作该视频的确切参数。作者[官方视频管线](https://github.com/aldegad/sprite-gen/blob/main/docs/video-pipeline.md)明确记录：参考静态图 → 按动作补画布 → Grok 连续视频 → 去背帧 → 选择周期 → strip/GIF/WebP。连续运动在视频模型阶段产生，切图只负责整理交付。当前两版图集是内置 imagegen 直接生成的实验，**不是执行了作者的管线**。

## 复现本地检查

在 ai-asset-pipeline 执行：

```sh
.venv-cutout/bin/python examples/make_anime_pilot.py --out output/mint-adventurer-pilot-v1
.venv-cutout/bin/python -m http.server 8770 --bind 127.0.0.1 --directory output/mint-adventurer-pilot-v1/viewer
```

已有目录会拒绝覆盖，复跑换新批次名。切图借用公开格式 descriptor 和本地 asset_bundle，不是 Aseprite 应用或 sprite-gen 实际导出。查看动作、暂停/逐帧、0.5 倍速和失败说明。

## 后续入口

保留现有工具项目 ai-asset-pipeline：生成服务提供真实连续帧，本地工作台检查身份、固定朝向、脚底注册、完整左右腿周期、接缝和动作缺项。先做单朝向 move，验收后再做 idle 与一次攻击。循环动作取完整周期；一次攻击保留准备、发力、随挥、收招，不能把所有动作都强制循环。
