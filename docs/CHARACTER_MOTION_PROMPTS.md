# 从没有素材到可制作动作

按顺序做两件事：先生成并确认一张角色参考，再基于它制作动作。若已有满意的全身角色图，直接跳到第二步。

## 第一步：生成参考图

下面整段复制给Codex即可。人物设定可替换，但姿态、构图和背景要求建议保留。

```text
请用当前GPT生图，设计一张二维横版游戏角色参考原画。
角色：可爱的三头身二次元少女冒险者，棕色齐下巴短发、琥珀色眼睛、左侧绿色蝴蝶结；白色短袖上衣、薄荷绿短裙、棕色短靴与手套、棕色斜挎小包，不携带武器。
画风：清晰线稿、柔和赛璐璐上色，服饰结构简洁，配色固定，小尺寸仍能辨认。
构图：向右稳定侧面，全身中性站姿，四肢自然分开，手脚完整，双脚在同一地面，人物居中，头顶和脚底留边距。
只有一个角色。透明背景，无场景、地面投影、文字、网格、多视角拼图或关节切片。
目标源画布512×512，人物占约85%高度，底部留约5%余量；实际尺寸不同需明确归一化，不能声称像素已经精确对齐。
先实际生成这一张图，保存为项目中的新文件，告诉我绝对路径。先不制作动作图集。
```

看参考图时确认：喜欢脸和衣服；四肢没有缺失或多出；侧面方向正确；脚和头没有被截断。若不满意，先修参考图，避免整套动作各自换脸。三视图可帮助设计，但动作生产的身份母版应是一张明确朝向的完整角色图。

## 每个字段怎么填

| 字段 | 含义与示例 |
|---|---|
| 参考图 | 第一步得到的图。把Codex返回的绝对路径填入，例如 `/你的项目/assets/hero-reference.png`；不要只填文件名 |
| 身份特征 | 固定发型、眼睛、衣服、配饰、体型和画风。写可观察的特征，不只写“可爱”；上面的角色描述可直接复用 |
| 动作 | 首次先验证待机、走路，再补出拳、受击、跳跃。每种写循环/单次、朝向和关键阶段 |
| 尺寸 | 源画布512×512用于制作；导出cell256×256包含透明留边；游戏显示高度128px是场景中的显示规格，三者不同。选128是起步示例，按实际游戏比例调整 |
| 节奏 | 动作总时长和阶段窗口。800ms走路指一次左右支撑完整周期，不是每帧800ms。8张均匀原画可各100ms，增加中间原画时重新分配而保持总时长 |
| anchor | 画布中的定位基准，通常与地面匹配。先要求Skill检查真实脚底再确定；`[0.5,0.95]`只是示例，不会自动识别脚底 |

## 第二步：制作完整动作的Prompt

替换参考图路径，整段发给Codex。以下节奏是起步方案，不是所有游戏通用的标准；技能需先结合角色与玩法确认。

```text
用 $character-motion-kit，先查看 /替换成真实绝对路径/hero-reference.png，基于它制作可复用的二维角色动作。
固定身份：三头身少女，棕色齐下巴短发、琥珀色眼睛、绿色蝴蝶结，白色上衣、薄荷绿短裙、棕色靴子和手套、斜挎小包；沿用参考图的脸、体型、服饰和画风。
统一向右侧面，源画布512×512、导出cell256×256，游戏显示高度暂用128px。保留透明留边，不逐帧按包围盒缩放。检查真实地面与脚底，再明确统一anchor。
先验证待机和走路，再补齐出拳、受击、跳跃：
- 待机：循环1600ms，站稳，可有轻微眨眼。
- 走路：左右支撑完整循环800ms，先设计接触、压低、经过、抬起等8个关键姿态；近远腿交替、手臂反向摆动。需要中间姿态时实际调用GPT生成，保持总时长；不要用淡入双影或关节切片代替原画。
- 出拳：单次330ms，前摇110ms、伸拳接触80ms、收招140ms，最后接回实际待机。
- 受击：单次160ms，有退缩和恢复，最后接回待机。
- 跳跃：单次440ms，暂定80ms离地、340ms落地。原画姿态与游戏整体高度分开，避免双重起跳位移。
这些时间先作为提案检查；参数有冲突先说明并修订。不要一次生一个大图集就声称完成所有动作。
用当前宿主GPT生图实际逐帧生成或定向修正，保存原图、真实提示词、参考顺序和失败版本。实际姿态决定逐帧时长并写入manifest。
检查身份一致、近远肢体、脚底、循环首尾及起停/收招连接。局部复用需要记录裁切范围，清除旧肢体残片；自动测试不能替代正常速度观看。
交付真实透明PNG、atlas与manifest、来源记录、逐帧工作台、正常速度动态对比和可操作Web示例；全部核心动作齐全后提供完整下载及Godot预览。保留草稿状态，正式游戏接入另行验收。
```

缺少姿态草图时可以让Skill先设计；你不需要手工准备每一帧。工具页的“填入起步示例”只填身份和节奏，不伪造已有参考路径，也不执行生图。

## 生图之后

页面第6至9步会根据实际产物类型、manifest、问题描述和目标项目生成后续Prompt。使用方法与每一步预期产物见[完整页面流水线](CHARACTER_MOTION_QUICKSTART.md#完整页面流水线)。不要在图片生成后直接结束：继续加工、实际正常速度检查、导出和目标游戏验证。
