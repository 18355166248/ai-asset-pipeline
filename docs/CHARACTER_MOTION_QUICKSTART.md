# 用 GPT 制作可复用的二维角色动作

在 Codex 中使用 `$character-motion-kit`，工具留在 `ai-asset-pipeline`，多个游戏共用。当前采用 Skill + 本地工具 + 验收网页；Python 管理素材和导出，真正生成由 Codex 内置 imagegen 完成。无需配置另外的 API key。网页不是可以自行调用宿主 GPT 的生图后台。

本机直接打开 [工具入口](http://127.0.0.1:8770/)：按角色设定、参考图、动作生图、图片加工、预览修正、导出、接入游戏继续制作；每一步整理可复制的Prompt给Codex执行。已生成图片可直接点第6步，不必重走角色设计。已有角色的对比、工作台、试玩和下载集中在折叠示例区，不代表你的新角色。

当前用户反馈十帧步态“有改善”，已转向完善工具入口。v23示例仍是草稿素材；Godot4.7.2实际导入与113项资源/动画播放检查通过，通用工具81项Python与37项Node测试通过，不代表目标游戏或真机验收。

## 准备什么

没有素材时，先按 [完整Prompt与字段引导](CHARACTER_MOTION_PROMPTS.md) 生成角色参考，再制作动作。工具入口提供角色预设、完整参考图Prompt、字段解释和生图后的四步操作引导。

| 材料 | 要求 |
|---|---|
| 角色参考 | 一张完整角色图。脸、服饰、手脚、武器清楚，画风和目标朝向明确；参考图不必透明，可以先用 GPT 设计 |
| 动作清单 | 如待机、走路、出拳、受击、跳跃。明确朝向、循环和关键姿态；攻击写出前摇、接触、收招，走路写两次不同的落脚 |
| 显示规格 | 游戏中的角色尺寸、统一源画布、导出 cell 与 anchor。anchor 是元数据，工具不会自动识别脚底 |
| 播放节奏 | 每帧时长、循环，以及起跳/落地/命中窗口；游戏物理另行匹配 |
| 姿态参考 | 推荐关键姿态草图或已认可的前后帧。它们控制姿态，最终素材仍来自实际 GPT 生成 |

二维角色不需要 GLB 或先做三维模型。这里的“真实生成图”是实际生成的最终原画，不要求把二次元角色变成写实照片。

## 直接这样使用

在 Codex 中提供参考图路径，发送例如：

> 用 $character-motion-kit，基于 /绝对路径/hero.png 制作右向二维动作：待机、八帧步行、出拳、受击、跳跃。保留这个角色的脸和服饰。输出统一256像素cell、脚底anchor为[0.5,0.95]。先确定动作时长和关键姿态，再调用当前GPT生图；失败版本保留，整套正常速度检查后给我试玩及素材包。

尺寸与 anchor 是示例，要按实际游戏确认。未指定时由 Skill 给出明确假设，不能默默沿用薄荷冒险者的裁切坐标或起落时刻。新图与旧版本分别存放，不覆盖原始生成图。

实际流程为：准备任务 → 看参考/草图 → GPT 逐帧生成或修正 → 导入原始图与真实提示词/参考顺序 → 选择候选 → 整套播放检查 → 导出。prepare 只生成计划，不等于已经生图。单帧通过也不等于步态通过。

## 得到什么，怎么用

| 交付 | 用途 |
|---|---|
| `bundle/atlas.png` + `bundle/manifest.json` | 通用二维素材：逐帧矩形、durationMs、loop、anchor，消费游戏直接读取 |
| 透明 `frames/` 与 Aseprite 数据 | 导入已有美术工具或接入自己的引擎打包器 |
| 逐帧工作台 | 1×播放、暂停、定位、整套动作检查；保持原画，不淡入两套肢体 |
| 可操作 Web 示例 | 验证移动、起停、跳跃、出拳/受击返回；不含完整战斗和关卡 |
| Godot 预览项目 | SpriteFrames资源与动画播放，保留时长和循环；物理/输入/战斗仍由目标项目接入 |
| 来源记录 | 实际原图、提示词、参考顺序、版本及失败原因留在生产工作区；下载只包含现有包内审查副本 |

素材包从 draft 开始。人工检查和目标游戏运行后，再按游戏资产规范采用；网页或测试通过不会自动批准正式美术。

## 已有素材怎样导出

以下命令在工具仓库根执行，使用新输出目录：

```bash
.venv-cutout/bin/python src/motion_preview_site.py \
  --manifest output/my-hero/bundle/manifest.json \
  --out output/my-hero-delivery-v1

.venv-cutout/bin/python -m http.server 8770 --bind 127.0.0.1 \
  --directory output/my-hero-delivery-v1
```

打开本地8770入口。完整交付需要五个核心动作；仅已有待机/攻击时先使用 `character_workbench.py` 检查，不伪造缺失动作。自定义起落、落脚和停步片段通过 `--controller-options <JSON>` 配置；缺参数时的示例默认值未必适合你的角色。

本地工具入口改为 React 应用，不再生成 toolkit.html：

```bash
npm ci --prefix workbench --ignore-scripts
npm run dev --prefix workbench
```

打开 http://127.0.0.1:8770/pipeline；已有图片从第6步继续。动作编辑在 /motion。生产构建用 `npm run build --prefix workbench`，本地检查用 `npm run preview --prefix workbench`。更多架构与清理范围见 [前端指南](FRONTEND.md)。导出的离线预览包仍可独立启动，但请使用其他端口，避免占用本地前端8770。

## 判断该修哪里

两版循环动作需要比较时，使用通用同步页：

```bash
.venv-cutout/bin/python src/motion_compare.py \
  --config input/codex/mint-adventurer-compare-v1.json \
  --out output/my-comparison-v1
```

配置里换成自己的两个manifest和action；双方画布、anchor及总循环时长需相同。工具支持不同帧数和不等逐帧时长，共享毫秒时钟播放真实原画，可定位参考帧。页面与图集自包含，复制输出目录并用HTTP打开即可；示例截图不构成新角色美术验收。

- 首尾身份或脚底变化：先比较原画和统一画布，不按各帧包围盒缩放角色。
- 半个步态反复出现：核对近远腿和手臂前后交换，增加帧数不能替代相位设计。
- 跨动作突然跳：核对首尾姿态、实际总时长和消费端选帧；能复用末帧待机时明确记作复用。
- 局部拼接不自然：缩小有效区域或重新生成该姿态，保留失败整帧。局部可用不能登记为整帧通过。
- 短按或不同落脚不能停下：使用已制作的起停片段；落脚映射与反向起步取消只复用真实原画，不自动画制动惯性。

详细命令、动作规格、版本记录见 [GPT制作指南](GPT_MOTION_GENERATION.md)。当前入口展示薄荷冒险者v23：五核心动作加起步和两种停步，8动作43播放位置、30张不同RGBA；播放位置含复用，不能当生成次数。当前原画仍待美术验收。

## 完整页面流水线

前五步：角色设定 → 参考图Prompt → 确认参考图 → 动作与节奏 → 动作生图。没有参考图先从第1步开始，第5步发送实际生图请求后继续第6步。

| 步骤 | 页面需要填写 | 给Codex执行后，返回什么 |
|---|---|---|
| 6 图片加工 | 实际图片/目录/manifest绝对路径、产物类型、已有生成记录 | 透明帧、atlas、manifest绝对路径、本机预览地址 |
| 7 预览与修正 | 本批次manifest路径、预览地址、看到的问题 | 正常速度与逐帧预览、定点修正后新manifest、剩余问题 |
| 8 导出素材 | 第7步的manifest、实际动画人工确认、导出格式 | 新导出目录、ZIP、资源清单与验证范围 |
| 9 接入游戏 | 目标项目路径、已导出素材目录、接入范围 | 测试角色/场景、运行与回退方法、目标平台验收记录 |

如果不确定产物类型，第6步选“让Codex先检查”。只有角色参考图还需实际生成动作；图集先看布局再显式裁切；独立帧按实际动作顺序加工；已有包校验复用。已有素材时保留真实节奏，不套用页面起步默认值。缺少动作时通用导出仍可用，但不能伪造完整战斗试玩。

每个后续步骤都提供“整理Prompt”和“复制Prompt”。发送给负责制作的Codex聊天，执行后把返回的真实路径填回下一步。页面不会读取宿主文件或自动生图/加工；第7步预览链接只支持本机HTTP/HTTPS地址，链接由用户提供，页面不验证内容。

文字草稿保存在同源浏览器的本地存储，兼容旧五步版本的文字草稿；图片不上传、不保存，身份确认与动画验收状态不持久化。上游身份变化会撤销参考确认；素材、动作、时长和manifest变化撤销导出确认，并清除旧Prompt，防止误用旧候选。
